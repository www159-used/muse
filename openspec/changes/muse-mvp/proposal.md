## Why

用户希望有一个独立运行、仿 Neovim 操作体验的终端音乐播放器，并且希望第一版保持简单。先解决歌曲如何导入、保存和播放，再逐步增加功能。

本变更已实现音乐库存储、本地导入和终端浏览；用户随后要求实现播放后端，具体实施由 `native-playback` 变更接续。工程骨架、CI 与发布流程由 `project-foundation` 变更建立。用户已接受的方向、本轮实现选择与后续待讨论细节分别记录在 design.md。

## What Changes

- 提供独立终端界面，以歌曲列表、状态栏和应用内命令行为基本形态。
- 使用 Rust 开发独立终端音乐播放器。
- 播放作为 workspace 内的 `muse-playback` 库，基础接口与 native 后端分开启用，应用使用内置 Rust 播放。
- 通过 `:import <文件路径>` 或 `:import <目录路径>` 导入本地音频，目录默认递归扫描子目录，优先适配网易云音乐的本地下载目录。
- 导入信息来自指定目录内的音频标签、NCM 元数据及关联附件，首版不读取网易云客户端数据库，未安装客户端的机器也可以导入该目录。
- 将歌曲信息和音频内容一起保存在 SQLite 格式的 `library.muse` 中。
- NCM 在导入时解包，库内保存完整的 MP3/FLAC 音频，源目录中的 NCM 保留。
- 使用源文件和库内音频的两次 SHA-256 检查去重，并用数据库唯一约束保证不重复收录；同曲不同字节的版本分别保留。
- 歌曲、音频和成功导入记录在同一事务中提交，导入成功后独立于原文件。
- 存储模块提供删除歌曲的操作，删除时完整清理对应音频、附件关联和成功导入记录，保留本地源文件，使原文件可以重新导入。
- 目录导入遇到个别文件失败时继续处理其他文件，保留已成功导入的歌曲，并汇总成功、重复和失败及失败原因。
- 将能够关联到歌曲的本地已有封面和歌词一起保存在库内，缺失内容不联网补齐；重复导入时可以补齐缺失附件，首版暂不展示封面和歌词。
- 从音乐库选择歌曲播放；首次启动、暂停恢复、曲终、错误、退出及导入期间的交互方案在设计文档中继续收敛。

## Capabilities

### New Capabilities

- `music-library`: 歌曲、音频及本地已有附件的持久化、完整导入、内容去重、读取和删除清理。
- `terminal-player`: 独立终端界面、命令输入和选择歌曲播放的最小流程。

### Modified Capabilities

无，当前没有既有实现或规格。

## Impact

- 新增音乐库存储、终端交互和播放控制的需求与设计。
- Rust 是已确认的开发语言，SQLite 是已接受的存储方案；实现采用 Ratatui/Crossterm 和 Rust NCM 读取器，播放接口由 `playback-interface` 建立，内置后端由 `native-playback` 接续。
- 新增内部 muse-library crate、结构初始化 SQL、导入回归样本、终端导入流程与任务清单；内置播放和终端接入的验证记录见 `native-playback`。

## Non-goals

第一版暂不考虑在线歌曲/歌单导入、独立播放队列、歌单编辑、账号体系、歌词和封面展示、频谱、插件系统和后台播放。封面和歌词仅保存本地已有且能够关联到歌曲的内容，不联网补齐。
